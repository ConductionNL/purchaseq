## ADDED Requirements

### REQ-CAT-001: Review Catalog Item Usage Statistics

Catalog managers must be able to view which `CatalogItem` objects are most frequently
ordered, in what quantities, and by which cost centres or departments.

#### Scenario 1.1: Catalog usage statistics overview

- **GIVEN** a catalog manager opens the Catalogus Analytics view
- **WHEN** the page loads
- **THEN** a `CnTableWidget` shows the top 20 most-ordered catalog items, with columns:
  Artikel, SKU, Categorie, Aantal bestellingen, Totaal besteld (stuks), Totale waarde (€)
- **AND** the table is sortable by each column

#### Scenario 1.2: Usage statistics filtered by period

- **GIVEN** a catalog manager is viewing the usage statistics
- **WHEN** they apply a date filter (e.g. "Q1 2026")
- **THEN** the table updates to show only orders placed within that period
- **AND** catalog items with zero orders in the period are hidden from the table

#### Scenario 1.3: Usage detail for a single catalog item

- **GIVEN** a catalog manager clicks on a `CatalogItem` row in the usage table
- **WHEN** the detail page opens
- **THEN** a timeline chart shows order volume over time for that item
- **AND** a related-orders section lists `ProcurementOrder` objects linked to this item

#### Scenario 1.4: Export catalog usage report

- **GIVEN** a catalog manager is viewing usage statistics
- **WHEN** they click "Exporteren"
- **THEN** `CnMassExportDialog` opens and the exported file includes all visible columns
  and rows for the selected filter

### REQ-CAT-002: Product Catalog with Inventory Tracking

Warehouse and procurement officers must be able to track inventory levels for items in the
`ProcurementCatalog` using `InventoryItem` and `InventoryStock` objects. Low-stock items
trigger a `NotificationService` alert.

#### Scenario 2.1: Inventory level widget on dashboard

- **GIVEN** `InventoryItem` objects exist with current stock levels
- **WHEN** the inventory widget loads on the dashboard
- **THEN** a `CnTableWidget` shows items with columns: Artikel, Huidig voorraad, Minimumdrempel,
  Status (Voldoende / Laag / Uitgeput)
- **AND** items with stock ≤ minimum threshold are shown first

#### Scenario 2.2: Low-stock notification

- **GIVEN** an `InventoryItem` stock level drops to or below its `minimumStock` value
- **WHEN** the inventory level is updated via `ObjectService.saveObject()`
- **THEN** a Nextcloud notification is sent via `NotificationService` to the assigned
  procurement officer
- **AND** the notification text is translated (Dutch: "Voorraadwaarschuwing: [artikel] onder minimumdrempel")

#### Scenario 2.3: Inventory level update

- **GIVEN** a warehouse employee opens an `InventoryItem` detail page
- **WHEN** they edit the `currentStock` value and save
- **THEN** the `InventoryItem` object is updated in OpenRegister via `ObjectService.saveObject()`
- **AND** the audit trail records the change with before/after values (AuditTrailService, automatic)

### REQ-CAT-003: Order Confirmation Tracking

Procurement officers must be able to track whether `ProcurementOrder` objects have been
confirmed by suppliers, and see the confirmation status on the dashboard and order list.

#### Scenario 3.1: Order list shows confirmation status

- **GIVEN** a procurement officer opens the Inkooporders list view
- **WHEN** the list renders
- **THEN** each `ProcurementOrder` row shows a `CnStatusBadge` with the confirmation status:
  Niet bevestigd / Bevestigd / Gedeeltelijk bevestigd / Afgewezen
- **AND** unconfirmed orders older than 3 business days are highlighted

#### Scenario 3.2: Confirmation status updated

- **GIVEN** a procurement officer receives a supplier confirmation
- **WHEN** they update the `confirmationStatus` on the `ProcurementOrder` to "Bevestigd"
- **THEN** the status badge updates immediately in the list view
- **AND** any linked `SupplierPortalUser` is notified via `NotificationService`

#### Scenario 3.3: Filter orders by confirmation status

- **GIVEN** the procurement officer is on the order list page
- **WHEN** they apply the filter "Niet bevestigd" via `CnFilterBar`
- **THEN** only `ProcurementOrder` objects with `confirmationStatus` = "Niet bevestigd" are shown
- **AND** the filter chip is visible and can be dismissed

### REQ-CAT-004: Delivery Note Generation for Goods Shipment Tracking

Warehouse staff and logistics coordinators must be able to generate a PDF delivery note
from a `GoodsReceipt` object. The PDF is generated by `DeliveryNoteService` using a
docudesk Twig template and attached to the `GoodsReceipt` via `FileService`.

#### Scenario 4.1: Generate delivery note from GoodsReceipt

- **GIVEN** a warehouse employee opens a `GoodsReceipt` detail page
- **WHEN** they click "Pakbon genereren"
- **THEN** `DeliveryNoteService` resolves the linked `PurchaseOrder`, `Supplier`, and
  `ProofOfDelivery` objects via OpenRegister relations
- **AND** a PDF is generated from the docudesk template and attached to the `GoodsReceipt`
  via `FileService`
- **AND** the PDF filename follows the pattern `pakbon-{GoodsReceiptRef}-{date}.pdf`

#### Scenario 4.2: Delivery note is accessible from the files tab

- **GIVEN** a delivery note PDF has been generated for a `GoodsReceipt`
- **WHEN** any user with access opens the `GoodsReceipt` detail page
- **THEN** the generated PDF is visible in the `CnObjectSidebar` → `CnFilesTab`
- **AND** they can download or share the PDF directly from the sidebar

#### Scenario 4.3: Delivery note generation fails gracefully

- **GIVEN** a `GoodsReceipt` is missing a linked `Supplier` or `PurchaseOrder` relation
- **WHEN** the user clicks "Pakbon genereren"
- **THEN** an error message is shown (not a stack trace) explaining what data is missing
- **AND** the error is translated in both Dutch and English (ADR-007)

### REQ-CAT-005: Purchase Order Creation with Online Delivery Tracking and Bill Matching

Procurement officers must be able to create `PurchaseOrder` objects with delivery tracking
enabled, and match received `VendorBill` objects against the PO.

#### Scenario 5.1: Create PO with delivery tracking

- **GIVEN** a procurement officer clicks "Inkooporder aanmaken" on the PO list page
- **WHEN** the `CnFormDialog` opens
- **THEN** it includes a "Levering volgen" toggle that, when enabled, creates a linked
  `GoodsReceipt` stub in OpenRegister upon PO save
- **AND** the PO and GoodsReceipt are linked via OpenRegister relation

#### Scenario 5.2: Bill matching against a PO

- **GIVEN** a `VendorBill` exists for a supplier and a `PurchaseOrder` exists for the same supplier
- **WHEN** a finance officer opens the `VendorBill` detail page and clicks "Koppelen aan PO"
- **THEN** a relation is created from `VendorBill` to `PurchaseOrder` in OpenRegister
- **AND** the `PurchaseOrder` status updates to "Factuur ontvangen"

#### Scenario 5.3: Bill amount mismatch flagged

- **GIVEN** a `VendorBill` total amount differs from the linked `PurchaseOrder` total by more than 1%
- **WHEN** the bill-to-PO relation is saved
- **THEN** a `MaverickSpendAlert` object is created in OpenRegister with the discrepancy details
- **AND** the linked procurement officer receives a Nextcloud notification via `NotificationService`

### REQ-CAT-006: Generate Annual Procurement Statistics

Procurement managers and controllers must be able to view an annual procurement statistics
report generated by `AnnualStatisticsJob`. The report is stored as a `Report` object in
OpenRegister and displayed on the dashboard.

#### Scenario 6.1: Annual statistics job runs on schedule

- **GIVEN** the `AnnualStatisticsJob` is registered as a Nextcloud background job
- **WHEN** the job runs (scheduled for 1 January, 00:00)
- **THEN** it aggregates `SpendTransaction`, `PurchaseOrder`, and `GoodsReceipt` data for
  the prior fiscal year
- **AND** a `Report` object is saved to OpenRegister with total spend, PO count, supplier count,
  and category breakdown

#### Scenario 6.2: Annual statistics report displayed on dashboard

- **GIVEN** an annual `Report` object exists for the prior year
- **WHEN** the dashboard loads the annual statistics widget
- **THEN** an `AnnualStatsWidget` (using `CnStatsBlock`) displays: Totale inkoop, Aantal PO's,
  Aantal actieve leveranciers, Grootste categorie
- **AND** a "Volledig rapport bekijken" link navigates to the `Report` detail page

#### Scenario 6.3: Manual trigger for annual statistics (admin only)

- **GIVEN** an administrator opens the Shillinq settings page
- **WHEN** they click "Jaarstatistieken herberekenen"
- **THEN** `AnnualStatisticsJob` is enqueued immediately via `IJobList`
- **AND** a success notification confirms the job has been queued
- **AND** this action is only available to admins (checked server-side via `IGroupManager::isAdmin()`,
  ADR-005)
